# Additional steps to build successfully:

1. Install required system dependencies:
   sudo apt-get update
   sudo apt-get install -y pkg-config libssl-dev nodejs npm

2. Initialize git submodules (required for moonlight-common-c):
   git submodule update --init --recursive

3. Build the Rust project:
   cargo build --release

4. Build the web assets:
   cd moonlight-web/web-server
   npm install --no-fund --no-audit
   npm run build
   cd ../..

5. Create static files symlink:
   ln -s moonlight-web/web-server/dist static

6. Configure server:
   - Edit server/config.json to set correct streamer_path: "./target/release/streamer"
   - Set your credentials and network configuration

7. Run the web server:
   ./target/release/web-server

# Windows WSL Configuration (for network access from other devices):

8. Create/edit C:\Users\<YourUsername>\.wslconfig on Windows:
   [wsl2]
   networkingMode=mirrored
   firewall=false
   dnsTunneling=true
   autoProxy=true

9. Setup Windows firewall (run as Administrator in Command Prompt):
   # Allow port 8080 through Windows Firewall:
   netsh advfirewall firewall add rule name="Moonlight Web Stream" dir=in action=allow protocol=TCP localport=8080
   
   # OR disable Windows Firewall completely:
   netsh advfirewall set allprofiles state off

10. If port 8080 is in use by IP Helper service, stop it (PowerShell as Administrator):
    # First, check what's using port 8080:
    netstat -ano | findstr :8080
    # Find which service is using the process ID:
    Get-WmiObject -Class Win32_Service | Where-Object { $_.ProcessId -eq <PID> } | Select-Object Name, DisplayName, State
    
    # Stop IP Helper service (common culprit):
    Stop-Service -Name "iphlpsvc" -Force
    # To re-enable later if needed:
    # Set-Service -Name "iphlpsvc" -StartupType Automatic
    # Start-Service -Name "iphlpsvc"

11. Restart WSL after config changes:
    wsl --shutdown
    # Then restart WSL/Ubuntu

12. Access server from other devices:
    http://<Windows-IP>:8080

# Auto-start Server on Boot (24/7 operation):

13. Create systemd service for auto-start (in WSL):
    sudo tee /etc/systemd/system/moonlight-web.service > /dev/null <<EOF
[Unit]
Description=Moonlight Web Streaming Server
After=network.target

[Service]
Type=simple
User=$USER
WorkingDirectory=/home/$USER/moonlight-web-stream
ExecStart=/home/$USER/moonlight-web-stream/target/release/web-server
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
EOF

14. Enable and start the service:
    sudo systemctl daemon-reload
    sudo systemctl enable moonlight-web.service
    sudo systemctl start moonlight-web.service
    
    # Check service status:
    sudo systemctl status moonlight-web.service

15. Configure Windows to auto-start WSL with server:
    # A PowerShell startup script has been created: start-moonlight-wsl.ps1
    # This script auto-detects WSL distributions and provides better error handling
    
    # Option 1 - Copy to Windows startup folder:
    # Copy start-moonlight-wsl.ps1 to Windows
    # Win+R, type: shell:startup
    # Create a shortcut that runs: powershell -ExecutionPolicy Bypass -File "path\to\start-moonlight-wsl.ps1"
    
    # Option 2 - Use Task Scheduler (Recommended):
    # taskschd.msc → Create Basic Task → Name: "Moonlight Web Stream"
    # → At startup → Start program → PowerShell
    # → Arguments: -ExecutionPolicy Bypass -File "C:\path\to\start-moonlight-wsl.ps1"
    # → Check "Run with highest privileges"
    
    # Troubleshooting WSL distribution names:
    # If you get "There is no distribution with the supplied name":
    # 1. Run 'wsl -l -v' in Windows to see available distributions
    # 2. The script auto-detects distributions and will try each one

16. Keep WSL running persistently:
    # Add to .wslconfig:
    [wsl2]
    networkingMode=mirrored
    firewall=false
    dnsTunneling=true
    autoProxy=true
    kernel=
    memory=4GB
    processors=2
    swap=2GB
    swapFile=%USERPROFILE%\\AppData\\Local\\Temp\\swap.vhdx
